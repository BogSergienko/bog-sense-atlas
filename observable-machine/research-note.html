The Observable Machine

A finite laboratory for recurrence, non-identifiability and reconstruction.

Research vision: Bogdan Sergienko. Mathematical implementation, verification and editorial assistance: CCAI KAI / ChatGPT. Version 0.1.0 presents a public, self-contained mathematical research laboratory. No separate DOI is claimed for this page.

Abstract

An observed return is weaker than a full description of a dynamical system. We give three reproducible exercises: distinct component-period sets with the same least common multiple; different labeled histories with matching phase projections; and exact reconstruction when both the event sequence and full terminal state are available. All are finite mathematical models, with negative controls. The authorial cyclic view motivates the questions; these calculations do not establish a physical theory.

A. Cycle Return

For a finite list of integer periods pᵢ ≥ 2, let xᵢ(t) = t mod pᵢ. The first strictly positive joint return is T = lcm(p₁,…,pₙ). By the definition of least common multiple, T is divisible by every pᵢ and no smaller positive integer has this property.

The map from a period list to T is not injective. The lists (6,8,12) and (3,8) both have T = 24 and have different numbers of components. The list (5,8) has T = 40, a negative control against universal return equality. Among distinct 2- or 3-element subsets of {2,3,4,6,8,12}, exactly 12 yield 24; this finite enumeration is not a count of every possible cyclic system.

Additional observation: component-return marks distinguish the displayed lists. They still do not determine arbitrary unmeasured coupling or graph structure. This exercise implements ordinary LCM arithmetic, not a newly discovered parent law.

Source: World Entry III §4.2, the LCM-only control and proposed compatibility test; Living Canvas, finite parent-period reconstruction example. See the public Living Canvas research entrance for context.

B. Hidden History

Fix q ≥ 2 and X=(a,b,h) ∈ ℤ₂ × ℤq × ℤ₂. Define c(a,b)=a XOR (b mod 2), with projection π(X)=(a,b). A increments a only; B increments b only; J increments both. On each event first move the indicated counter(s), then set h′=h XOR c(a′,b′). The UI supports q ≤ 64 and at most 512 events per receipt.

Starting from (0,q−1,0), AB and BA end with phases (1,0). For odd q, AB has h=0 and BA has h=1. For even q, both end with h=0. Thus full final-state observation separates the odd example, but does not identify every history. The q=4 control is part of the claim, not an exception to conceal.

A retained intermediate phase observation separates these two particular histories. In contrast, starting from equal phases and different h, any future common event sequence gives equal phase observations: prove this by induction because each phase update is independent of h. No amount of such phase-only probing can recover the missing bit. This is a non-identifiability result for a declared observation class.

Sources: the public Cycle Clocks v1.1 event extension (A/B/J) and World Entry III §6.1–6.3, Eqs. (1)–(4), (6), (7), and §7 Eq. (10). The q=3 joint map has phase period 6 and full period 12; q=4 has full period 4. An order-sensitive marker is not an irreversible archive of all events.

C. Reconstruction

For a known event e let δa,δb be its indicated increments. The exact inverse is h=h′ XOR c(a′,b′), a=(a′−δa) mod 2, b=(b′−δb) mod q. Each event is a permutation. To reverse a word, apply these inverses in reverse order. Composition of permutations remains bijective, so one full terminal state plus the exact event record has one origin.

If only terminal a,b survive, there are exactly two possible full terminal states and hence exactly two possible origins under the same word. Inversion does not create the missing observation. Unknown event records introduce further ambiguity. Flipping a claimed output bit produces a receipt that the verifier rejects; removing h from an observation is a different experiment from corrupting it.

The independent Python verifier computes phases from cumulative event counts and h from a parity sum. Exhaustive origin search in the acceptance suite uses forward enumeration rather than the JavaScript inverse. Both implementations are fully supplied, so free claims require no paid materials.

Reproduction

  1. Open index.html locally; run A, B and C.
  2. Download a JSON receipt from C.
  3. Run python verify.py receipt.json. Run python verify.py for the seven published witness/control assertions.
  4. The free reproducibility package also includes the JavaScript/Python acceptance suite. Run python tests/acceptance.py with Python 3.9+ and Node 18+.

The generated receipt contains q, the initial state, labels, output and every intermediate state. It is a public formula trace, not a cryptographic execution attestation. Integrity manifests bind downloaded bytes, not scientific truth or authorship.
